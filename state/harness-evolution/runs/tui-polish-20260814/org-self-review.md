# Organization self-review

## Verdict

The permanent organization stayed Principal / Analyst / Builder / Critic. No permanent worker was added. Advisor, Freeze Critic, temporary Workers, and independent Reviewers ended within this run.

## What worked

- **Authority separation:** Advisor froze D01–D29; Freeze Critic accepted; Workers implemented bounded slices; independent Critics scored. No implementer authored accepted scores.
- **One Writer:** held across nine implementation iterations. Workers never overlapped on `lib/tui/`; the Principal owned full pytest, PTY, parity, visual gates, and closeout.
- **Debate changed implementation:** Critics cut broad feature piles into coherent state machines, bound exact structured ask/confirm/evidence semantics, rejected provider signature churn, specified chip-safe PTY absence needles, and required filesystem recency rather than invented status fields.
- **Evidence corrected confidence:** native greens did not conceal real-PTY focus, drain, SIGWINCH, empty-artifact, or interrupt-card timing defects. Every iteration retains debate, test outputs, notes, independent scores, and Reviewer gate.
- **Stop discipline:** the original five-iteration run recorded FAIL rather than deleting the shipped cockpit or claiming convergence. The owner explicitly authorized iter-6…iter-10 without amending the freeze. Iter-9 became the first all-pass, so iter-10 was not started.
- **Independent final gate:** iter-9 Reviewer scored all 29 dimensions, minimum 9.0, and separately audited scope, score inflation, preservation, and the organization.

## Friction and gaps

- The original five iterations spent too much budget on already-partial identity/targeting and follow-on regressions while known zero-score ask/evidence/confirm/splash seams remained untouched.
- Several Worker slices relied on native tests where terminal behavior was load-bearing. Principal full gates found focus theft, provider drain, and a failed-card paint race later than ideal.
- Reviewer reports repeatedly restated stable dimensions. The rigor was useful; the prose volume was not. Changed-dimension scoring plus a machine-checked stable baseline would reduce turnaround without self-grading.
- The pre-implementation iter-9 Critic write failed once and left a truncated debate file. A replacement Critic completed it before the Worker began; this preserved process but added avoidable delay.
- A debate needle demanded idle `@Principal` after a typed `@Builder` turn. The Worker/Principal corrected it against the higher-authority freeze. Contracts should distinguish idle defaults from session-local state.
- PTY fixtures with long pytest temp paths can alter 40-column wrapping. The final test uses a short temporary provider path and still exercises the real executable seam; future harnesses should make geometry-sensitive fixture paths explicit.

## Changes for future runs

1. Schedule every 0.0 function before lifting 8.x presentation dimensions.
2. Any provider, focus, dock, or resize change gets a real PTY row in the same slice.
3. Define PTY observations as normalized per-invocation or per-reflow deltas; distinguish persistent screen content from newly emitted terminal bytes.
4. Bind fixture path length when compact wrapping is part of acceptance.
5. Generate the stable score-table shell from the frozen schema; reserve Critic prose for changed dimensions, regressions, bias, and org critique.
6. Make task artifact writes atomic so a failed Critic cannot leave a plausible truncated contract.
7. Keep the four permanent roles unchanged. The observed failures were sequencing, contract precision, and proof-harness gaps—not missing organization capacity.
